# Claude Monitor CYD

## Project Overview

Physical desktop dashboard for Claude.ai usage monitoring on an ESP32-2432S028 "Cheap Yellow Display". Two-screen touchscreen UI showing real-time utilization data fetched directly from the Claude.ai API.

**Hardware**: ESP32 CYD (320x240 2.8" ILI9341 LCD, XPT2046 touch, CH340 USB, WiFi/BT)
**Status**: Working on hardware. WiFi mode primary, USB serial fallback.

## Architecture

```
Mac: bridge_auto.py (Claude.ai API) --WiFi/USB--> ESP32: LVGL UI
```

- **Bridge** calls `claude.ai/api/organizations/{uuid}/usage` directly — accurate 5h + 7d utilization %
- **Transport**: WiFi HTTP POST to `claude-monitor.local/api/monitor` (primary), USB serial fallback
- **LaunchAgent**: `~/Library/LaunchAgents/com.claude.cyd-bridge.plist` (session key stored here, outside git)

## Key Technical Details

### Display Driver
- Raw HSPI SPI (NOT TFT_eSPI — library doesn't work with this CYD variant)
- X-mirror fix in LVGL flush callback (pixels written in reverse column order)
- XY-mirror fix in touch callback (`319 - x`, `239 - y`)
- SPI speed: 20MHz, SPI_MODE0

### LVGL Configuration
- Color depth: 16-bit RGB565
- Heap: 48KB
- Draw buffer: 320 x 20 lines (partial rendering)
- Fonts: built-in Montserrat 10 + 12 + 14 + 22 + 28 (Latin + LVGL symbols), plus
  `cm_cyr_12` / `cm_cyr_16` with Cyrillic for chat titles, regenerated with:
  ```bash
  npx lv_font_conv@1.5.2 --font firmware/.pio/libdeps/cyd/lvgl/scripts/built_in_font/Montserrat-Medium.ttf \
    -r 0x20-0x7E,0xAB,0xB0,0xB7,0xBB,0x400-0x45F,0x490-0x491,0x2013-0x2014,0x2026,0x2116 \
    --size 16 --bpp 4 --format lvgl --no-compress --lv-include lvgl.h -o firmware/src/fonts/cm_cyr_16.c
  ```
- Widgets enabled: Label, Bar, Btn, Obj, Image
- NEON/Helium .S assembly files must be deleted after `pio run` (ARM-only, breaks Xtensa)

### Data Model
Bridge sends JSON payload every 30s:
```json
{
  "fh_pct":        42,    // 5-hour utilization % (from Claude.ai API)
  "fh_reset_min":  183,   // minutes until 5h block resets
  "sd_pct":        15,    // 7-day utilization %
  "sd_reset_min":  4320,  // minutes until 7d block resets
  "warning_level": 1,     // 0=ok 1=50% 2=75% 3=90%
  "plan_name":     "Pro",
  "waiting":       1,     // Claude Code sessions waiting for you
  "wl":            "r|12|Монитор подвис|claude-monitor-cyd",  // up to 5: kind (r/p/q)|minutes|title|project
  "working":       1,     // sessions where Claude acted in the last 2 min
  "xp_add":        42     // Claude's actions since the last push (a delta)
}
```
Sent as UTF-8 (`ensure_ascii=False`): the device's JSON reader copies bytes
and does not decode `\uXXXX`.

### Transport Protocol
- Baud: 115200 (USB serial fallback)
- PC→CYD: `{...}\n` JSON payload
- WiFi: HTTP POST to `http://claude-monitor.local/api/monitor`
- Device endpoints: `GET /api/status`, `POST /api/monitor`, `POST /api/config`, `POST /api/pet`
- `/api/monitor` accepts partial payloads: missing fields keep their values. The bridge
  uses this to push `{"waiting":N}` the moment it changes, between 60s usage polls.

### Air Raid Alerts (alerts.in.ua)
- Fetched **by the device itself**, like the weather — not via the bridge, so the
  indicator survives the Mac sleeping or the bridge dying.
- Endpoint: `GET /v1/iot/active_air_raid_alerts/{uid}.json` → one char `A`/`P`/`N`
- Polled every 30s (rate limit is 8-10 req/min); no answer for 3 min → `UNKNOWN`
- **UID 1293 = м. Харків** (city hromada). The UID directory flags it outright:
  *"Тривоги в місті оголошуються окремо від області чи району"* — the city is
  announced independently. Neither the oblast (22) nor the raion (124) tracks it:
  measured with the city calm, raion 124 answered `A` and oblast 22 answered `P`,
  because outlying raions and border hromadas were under alert.
  Full UID list: the Google Sheet linked from https://devs.alerts.in.ua
- Token + UID live in NVS (namespace `cyd`, keys `al_token` / `al_uid`), never in git.
  The token's only copy on the Mac is `ALERTS_IN_UA_TOKEN` in `~/.yapiko.env`:
  ```bash
  set -a; . ~/.yapiko.env; set +a
  curl -X POST http://claude-monitor.local/api/config \
       -H 'Content-Type: application/json' \
       -d "{\"alert_token\":\"$ALERTS_IN_UA_TOKEN\",\"alert_uid\":1293}"
  ```
  `/api/status` reports `has_token` but never echoes the token back.

### Two Screens
1. **Monitor**: clock/date, weather (Open-Meteo), air raid icon + stripe,
   three compact limit rows (5H with live countdown, 7D, per-model cap),
   the pet's room (y=163..268) and its status row (level, XP, rewards)
2. **Settings**: WiFi provisioning (AP mode), timezone ±

Alert states drive both the header icon (in the gap between clock and weather)
and the `accent_bar` stripe under the header:
| State | Icon | Stripe |
|---|---|---|
| `ALERT_ACTIVE` | red ⚠ | red |
| `ALERT_PARTIAL` | orange ⚠ | orange |
| `ALERT_CLEAR` | hidden | dim |
| `ALERT_UNKNOWN` | dim ↻ | dim |

The icon is centred on the header's midpoint (x=120), not on the gap before
the weather box: the temperature is right-aligned in a 114px box at x=118, so
the visible empty space runs x=80..157. The label keeps a 38px box with
centred text because the glyphs differ in width (warning 31.5px, refresh
28.0px). Its `y` matches the clock's; the warning glyph's own `ofs_y=-4`
already sits it lower.

### Pet (`src/claude_pet.h`)
The Claude Code mascot as a small tamagotchi in the room under the limits.

**Graphics.** Every sprite and the unlock/achievement tables live in
`scripts/gen_pet_sprites.py`; it bakes them ×4 (Claude and what he wears) or ×3
(room, companions) into RGB565A8 arrays in `src/pet_sprites.h` (~380 KB of
flash; flash is ~88% full). LVGL blits uncompressed images straight from flash
with no RAM copy; palette images would be expanded to ARGB8888 in RAM on every
draw, which the 48 KB heap can't carry. After editing a grid:
`python3 scripts/gen_pet_sprites.py`, then rebuild. Positions of worn things
are art cells relative to the frame's left edge and the top of the head; held
things hang from the left-hand cell the generator finds in each frame.
Reference page (all levels, items, achievements, live screen):
https://claude.ai/artifact/7TqcLJwSLg54JMyKiF62uY

**XP and levels** — identical to a colleague's pet, so they compare one to one:
+10 answer finished (Stop; StopFailure gives none), +5 you answered a
permission or question, +15 subagent started, +20 context compacted. The same
event twice in a row in one session counts once (the bridge de-duplicates).
XP never goes down. Total XP for level L: `200 × (L − 1)²`. Measured pace over
two weeks of transcripts: ~2200 XP/day (Lv 10 ≈ a week, Lv 30 ≈ 2.5 months).

**Unlocks**: a thing on every level 2–30 (cap, duck, glasses, beanie,
headphones, poster, scarf, party hat, crown, crab, cloak until 22, shades,
coffee mug, hoodie, hachimaki, lava lamp, container whale, neon sign, server
rack, wizard hat, black katana, guitar, vyshyvanka, robot, cat, sunflower,
grimoire, wings, golden aura). One per slot is shown — the newest; long-press
the pet to pick the hat. Taps give hearts, not XP.

**Achievements** (15, medals on the room's shelf, grey until earned): first
answer, answer between 2–5 am, 5 days started before 9, three subagents at
once, a limit at 100%, 100 answers a day, 7-day streak, a week without 5H at
100%, 5 projects a day, 10 compactions, 100 taps, Saturday + Sunday, 1000
answers, 5 chats waiting at once, 100 replies to permissions/questions.

**State, highest priority first:** demo → joy (tap, level-up, achievement,
5H reset) → waiting (a chat waits for you) → exhausted (5H 100%: slumped, x x
eyes, smoke) → working (Claude acted in the last 2 min) → tired (5H ≥ 75%,
sweat from 90%) → sleep (night by the sleep-schedule hours) → bored (3 days
without Claude: sits under a rain cloud) → sleep (2 h idle) → idle (yawns now
and then from 5H 50%). Overlays: helmet during an air raid alert (replaces the
hat), umbrella in rain, scarf at ≤ 0 °C; the window shows day/night/rain/snow
and the room dims at night. Level-ups, unlocks and achievements queue up as
toasts in Russian.

Progress is one NVS blob (`cyd` / `pet`, `PET_PROGRESS_VERSION` 2), written at
most every 5 min plus on level-ups and achievements; a version bump resets it.

**Sessions and events.** `scripts/cyd_session_hook.sh` runs from hooks in
`~/.claude/settings.json`: Stop → `reply`; StopFailure → `failed`;
Notification `permission_prompt` → `permission`; Notification
`elicitation_dialog|agent_needs_input` → `question`; UserPromptSubmit,
PostToolUse, PostToolUseFailure → `busy`; SubagentStart → `agent`;
SubagentStop → `agent-end`; PreCompact → `compact`; SessionEnd → `end`. It
writes one file per session to `~/.claude/cyd-sessions/` (`waiting <kind>` or
`busy`) and appends `<session> <event>` lines to `.xp` (S answer, Q reply,
A/a subagent start/stop, C compaction); going busy right after "waiting
permission/question" is a Q. No network, always exits 0, synchronous so events
can't land out of order.

The bridge scans that directory every second (files untouched for 12 h are
swept), claims `.xp` by renaming it, de-duplicates, and pushes
`waiting`/`wl`/`working` the moment they change and the event counts
(`xs xq xa xc`, max concurrent subagents `ag`, CRC32s of projects that answered
`sp`) at most every 10 s. Chat titles come from the transcript: `customTitle`
(after `/rename`), else `aiTitle`, else the project folder. The device drops
`waiting`/`working` to 0 if the bridge goes quiet for 5 min.

**Dismissing.** Opening a chat and leaving it fires no hook, so a chat you've
seen stays "waiting" until you write to it. Tap the ticker row on the device to
hide the chat shown ("seen, not now"): each wait has its own id (CRC32 of
session + the moment it began waiting), so it comes back once that chat waits
again. Dismissals live in RAM (last 8) and also stop the pet waving for them.

**Waiting ticker** shows the chat title in «quotes» (a chat named after its
first message — "Монитор подвис" — otherwise reads like a device status) and
"<what> N мин · project folder" under it, where <what> is "закончил" (a
plain Stop: your turn), "спрашивает" (the answer's last paragraph has a '?',
read from the transcript), "просит разрешение" or "ждёт ввода"; chats started from `~` show no
project. A chat counts as waiting as soon as it waits
(`WAIT_SHOW_SEC = 0` in the bridge; it scans every second, so ~1 s to the
screen). A 60 s delay was tried to keep the chat you're typing into from
showing after every answer, and dropped: seeing a wait at once matters more.
While any chat waits, the 7D row becomes a ticker: title
(Cyrillic font, cut with "…"), "ждёт ответа / просит разрешение / задал вопрос ·
N мин", a coloured dot (blue / orange / yellow) and "1/3"; it rotates every
3 s. The 7D limit itself is the last slide of
the cycle (each waiting chat, then 7D, 3 s apiece), so an idle open session
can't hide 7D for hours; with nobody waiting 7D just stays.

**Checking the art on the screen:**
```bash
curl -X POST http://claude-monitor.local/api/pet -H 'Content-Type: application/json' \
     -d '{"state":"waiting","env":"rain","level":24,"sec":20}'
# states: idle working waiting tired sleep bored joy exhausted
# env: clear rain snow cold night alert       level: show that level's things
```
The `Content-Type` header is required on every device POST: without it curl sends a
form, and the ESP32 WebServer drops a form field that has no `=`, so the body arrives
empty and the request silently does nothing.
`/api/status` also reports `pet`, `level`, `xp` (total), `xp_next`,
`achievements`, `answers_today`, `streak`, `waiting`, and heap (`heap_free`,
`lv_free`, `lv_frag_pct`).

### Session Key
- Stored in `~/Library/LaunchAgents/com.claude.cyd-bridge.plist` (outside git, never committed)
- Get from: claude.ai → DevTools → Application → Cookies → `sessionKey`
- Expires in weeks/months. Bridge prints `[SESSION EXPIRED]` in `/tmp/cyd-bridge.log` when it does.

## Build & Run

### Flash ESP32
```bash
cd firmware
# Delete ARM assembly files if build errors occur:
find .pio -name "*.S" -delete
~/.platformio/penv/bin/pio run -e cyd --target upload --upload-port /dev/cu.usbserial-1340
```

### Run bridge manually
```bash
python3 scripts/bridge_auto.py --session-key sk-ant-sid02-...
```

### LaunchAgent (auto-start on login)
```bash
# Restart after plist changes:
launchctl unload ~/Library/LaunchAgents/com.claude.cyd-bridge.plist
launchctl load ~/Library/LaunchAgents/com.claude.cyd-bridge.plist
# Check log:
tail -f /tmp/cyd-bridge.log
```

## Coding Conventions

### C code (src/, firmware/)
- C99 for UI header (ESP32 Arduino toolchain compatibility)
- No dynamic allocation in UI — all objects created once at init
- `#ifdef ESP32` guards for platform-specific code
- `SERIAL_PRINTF` macro for debug output

### Python code (scripts/)
- `curl_cffi` with `impersonate="chrome120"` required to bypass Cloudflare on claude.ai
- `SessionExpiredError` raised on HTTP 401/403 — check for `[SESSION EXPIRED]` in log
